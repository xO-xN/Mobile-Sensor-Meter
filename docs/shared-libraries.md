# v0.4.3 固定共享库与手势执行边界

本版 manifest.schemaVersion 为 2，sharedLibraries 声明确切运行库。只在 App v1.6.2 或支持这些引用的 Host 中运行；旧 App 不能执行共享引用。本地 standalone 开发用 npm ci --ignore-scripts 安装 package-lock 的精确依赖，Host 运行不会安装或下载。

本工具明确声明 `scoreServer.needsHttps: true` 与 `supportsPerformerUrl: true`，因为手机传感器、摄像头和麦克风使用安全上下文 API。App 仅对这种明确需求启用已配置的 HTTPS 入口；普通工程默认 HTTP。共享库引用本身不构成 HTTPS 需求，QR、复制地址与页面连接使用 Host 决定的同一网址。

Host 注入 PNDS_SHARED_LIBRARIES JSON 映射。lib/shared-libraries.js 只接受本工程声明的固定 id/version/kind 与存在的绝对入口；Host 环境存在时缺项、错误版本或缺文件明确失败，不静默使用本地依赖。Node CommonJS 通过 requireLibrary 加载；浏览器资源由工程 /__pnds/shared/ 同源路由提供，手机和可信 HTTPS 使用相同含义。标准模块和工具策略仍属于工程。

共享 .pnds 只携带引用、源码与工程资产，不携带重复库或 node_modules；打包安装须由 App 检查接收方能力。Standalone 不注入该环境，继续使用精确本地 npm 依赖。公开 Node/HTTP/受控进程回归与真实设备验收分开记录；健康检查、HTTP 成功不能代表传感器、推理、诊断功能或声音已通过。

0.4.3 是本地修复候选，尚未发布。App 正式 Utilities 注册表仍锁定已发布的 0.4.2；维护者完成新版真机验收并发布固定工具产物后，App 才能引用新版真实 release URL 与对应 sha256。不得把本地候选写成已发布来源。

Mobile 的 ml5 1.4.0 与 tfjs/lite 模型分别检查：库由 /__pnds/shared/ml5.js 提供，模型仍在 public/vendor/handpose/。/handpose/assets.json 分别列出库、检测模型和关键点模型；fetch:handpose 只校验并补齐四个工程模型文件，运行时零 CDN。

## 手势模型的线程与就绪边界

手势启用后先申请摄像头，再在独立 Worker 内加载 ml5、初始化推理后端与模型，并执行首次和后续推理。页面只维持预览、采集画面并传递帧；倾斜、运动、麦克风的采集与 Socket.IO 发送不等待手势模型。Worker 或画面传递能力不可用时，只报告手势不可用，不回退到页面主线程运行模型。

加载状态按真实阶段显示：请求摄像头、加载识别引擎、加载手势模型、等待摄像头画面、准备首次识别。模型加载结束不表示已有识别结果；首次推理完成后才显示识别已就绪。未检测到手同样是有效的首次结果，不作为加载失败。推理耗时与更新率只统计真实推理完成，状态消息不计入采样率。

停止会终止 Worker、取消待完成请求并释放摄像头；迟到的模型消息和帧不得重新启动采集或覆盖停止后的状态。进入后台释放摄像头并停止推理，已经就绪的 Worker／模型保留在内存中，回到前台后重新取得摄像头并继续采集。显式停止后再次启用会创建新 Worker。权限守卫、采集 epoch、单调递增 seq、零值与缺失值的区别继续沿用原契约。

每次推理提交时保存该帧的宽高副本，结果按这个尺寸归一化；不能在推理完成时再读取当前视频尺寸，否则首推理期间的视频尺寸变化会造成坐标跳变。进入后台使已经提交的帧失效，即使结果在恢复前台后才返回，也不得作为新样本发送。
